# SkyFlow Designer（桌面版）

原生桌面版天空盒流动贴图（Flowmap）设计工具。由 Web 版 <https://github.com/1to3fall5/skyflow-designer>
移植而来，像素管线全部下沉到 Rust，前端只负责显示与交互。

## 架构

```
app/
├─ src-tauri/src/
│  ├─ engine/
│  │  ├─ buf.rs       RGBA 缓冲
│  │  ├─ ops.rs       无缝模糊 / 笔刷 stamp / 风向场 / 绕流扰动 / 魔棒 / 升采样
│  │  ├─ io.rs        图片解码（含 TGA）/ PNG·TGA 导出 / .skyflow 工程文件
│  │  └─ mod.rs       图层模型、合成管线、历史栈、脏矩形 diff
│  ├─ commands.rs     Tauri 命令层
│  └─ lib.rs
└─ src/               React + TypeScript 前端（2D 绘制视图 / Three.js 3D 预览）
```

**所有权模型**：Rust 持有全部图层像素（`Vec<u8>`），是唯一事实来源。
前端不做任何像素运算，只做 `putImageData` 显示。

**数据流**：指针事件在前端聚合成折线 → 每帧一次 IPC 发给 Rust → Rust 并行合成 →
只回传变化的矩形（脏矩形 diff + base64）→ 前端 `putImageData`。

**状态回流**：每个变更命令的 `Snapshot` 都自带一份 `StateResp`（引擎最新状态）。
前端分两条消费路径：

- `applySnap` — 热路径，只推像素、不触发 React 重渲染。仅用于 `stroke` / `flood_fill`。
- `applyUpdate` — 冷路径，先 `setState` 再推像素。投影、张角、尺寸、图层增删排序、
  undo/redo、新建/打开都必须走这条，否则 `state.projection` 会停在初始值，
  3D 预览的球体/平面切换和 `uProjectionType` 就永远不生效。

`src/app-wiring.test.ts` 用源码级断言把这条约定钉死。

## 图层的绘制语义

| 图层 | 可绘制内容 | 说明 |
|---|---|---|
| 流向 `paint` | 内容 | RG = 流向，直接画 |
| 路径 `path` | 内容（由几何生成） | 钢笔的锚点存在这里，像素每次从锚点重新算出来 |
| 风向 `wind` | 遮罩 | 内容由「方向 / 强度」参数生成，笔刷只画作用范围 |
| 障碍 `obstacle` | 遮罩 | 内容由「扰动 / 范围」生成，笔刷只画障碍区域 |

调整层（风向 / 障碍）的遮罩**从空开始**（alpha 0）。在调整层上落笔永远编辑遮罩，
不存在「当前模式不对所以画不上」的情况。

路径层和流向层一样画的是**内容**，不是遮罩——它只是把「画了什么」记成了锚点而不是
像素。所以它的「属性」面板里没有参数可改，笔刷在选中一条路径后才由选项栏接管。

### 图层顺序决定谁覆盖谁

图层列表**第一行是最上层**：越靠上越晚合成，因此覆盖下方的一切，和 Photoshop 一致。

- 拖动行可调整顺序（整行都是拖拽区，抓名字或标签也行）；也可用工具栏的 ▲▼ 移动当前图层。
- 顺序是**逐像素生效**的。障碍层不再无条件生效：在它上方新建一层流向层并涂抹，
  涂到的区域会重新变成可流动（B 通道回到 255），没涂到的地方仍然被挡住。
  反过来，把障碍层放到流向层上方，它照旧挡住下面的流向。
- 实现上，障碍的 B 通道写入放在合成循环**之内**该图层的栈位上，而不是循环结束后
  再补一遍。放在循环外会让障碍变成全局无条件，无论上面涂多少都改不动。

对齐 Photoshop 的骨架：

```
┌──────────────────────────────────────────┐
│ 文件 编辑 视图 图层 帮助   未命名工程 * ─□✕│ ← 标题栏与菜单栏合一
├──────────────────────────────────────────┤
│ 选项栏 · 跟随当前工具          [屏幕模式] │
├────┬──────────────────────┬──────────────┤
│ 工 │                      │ 属性          │
│ 具 │                      │ 图层          │
│ 箱 │  3D 预览（默认）      │ 视图         │
│    │  分隔条可拖           │ 文档 ▸ 导出 ▸ │
├────┴──────────────────────┴──────────────┤
│ 状态栏 · 分辨率 / 缩放 / 合成耗时 / 图层   │

```

每个面板内部再分节，节与节之间是一条通栏细线：

```
┌────────────────────┐
│ 图层               │ ← 卡片头，比面板体亮一档
├────────────────────┤
│ ✎ ✒ ≋ ⬡ │ ✦ │ ⌃ ⌄ │ 🗑 │ ← 图标工具栏（✦ 加效果）
├────────────────────┤
│ 不透明度  [====] 100%│ ← 图层栈的问题，所以在这里，不在属性
├────────────────────┤
│ 👁 ▨ 全局风向  遮罩 │ ← 缩略图画在棋盘格上，选中是整条浅灰
│ □ ▨ 流向 1     fx  │   可见性：眼睛＝显示，空心方格＝隐藏
│ 👁 ▨ 障碍物        │   fx＝这一层挂着效果
├────────────────────┤
│ 👁 模糊   [==——] 12 │ ← 选中层的效果，缩进到缩略图列
└────────────────────┘
```

- **应用栏**（顶部唯一一行）：菜单在左（文件 / 编辑 / 视图 / 图层 / 帮助），
  窗口按钮在右。`decorations: false`，所以**没有独立的窗口栏**——这就是 PS 在
  Windows 上的样子。中间空白处可拖动窗口，双击最大化。
  新建、打开、**打开最近**、保存、导入天空图、导出都在「文件」里；视图开关带勾选。
- **工具箱**（左，竖排）：画笔 `B` / 钢笔 `P` / 橡皮擦 `E` / 魔棒 `M` / 吸管 `I` / 平移 `H`。
- **选项栏**：跟着工具变——画笔给 `大小 · 硬度 │ 强度 · 透明度`（两组，见下），
  钢笔给 `大小 · 硬度 │ 强度` 加路径状态，魔棒给 容差；
  右端是屏幕模式（2D 绘制 / 分屏 / 3D 预览），PS 也把它放在选项栏最右。
- **面板区**（右）：一个 dock。默认 **属性在最上**（跟随选中图层，PS 亦如此），
  下面是图层、视图，文档 / 导出默认折叠——但**拖标题栏就能换位置**。
  每个面板和面板内的分节都能折叠，`Tab` 一键全部隐藏。
- **状态栏**（底部）：只读。放控件会抢走画布焦点。
- 2D / 3D 之间的分隔条可拖（15%–85% 夹紧，避免拖没了抓不回来）。

默认打开 **3D 预览**：flowmap 只有在天空上动起来才读得出是 flowmap；2D 是干活的地方，
按 `1` 一秒到，不用当默认。

### 面板的版式照 PS 的语法来

面板原来是一堆「标签 | 裸滑轨 | 带颜色的数字」扎在圆角卡片上——那是设置页的语法，
不是图像编辑器的。PS 的面板是另一套语法，三件事让它一眼能读：

| PS 的做法 | 这里 | 为什么 |
|---|---|---|
| **分节**：箭头标题 + 一条通栏细线 | `.sect` / `.sect-head` / `.sect-body` | 线走满整宽、标题文字内缩，分界就清楚了，不用给每组加边框。属性面板因此只留「这一层是什么」那一节，而不是一张平铺的表 |
| **字段**：数值装在凹陷的框里 | `.row-value` | 框才是「这是你的值」的信号；面板上的彩色文字读起来是注释，之前就是这个问题 |
| **图标**：面板自带一条图标工具栏 | `.pbtn` + `IconBtn` | 六个两字标签（`＋ 流向` `－` `▲`）吃掉了缩略图和图层名需要的宽度 |

另外两处是为了把这些装进去：

- **滑轨填色**：`a range` 的轨道**就是**它的背景，所以 `<Range>` 只写一个 `--p` 自定义
  属性就能画出 PS 那种左填色轨道，不需要一个会夹住滑块的包裹元素。轨道是凹陷的、
  滑块是中性的——颜色在填充里，不在握把上。
- **图层缩略图**：每层一张 32² 的 PNG（`layer_thumbs` 一次批量返回），画在棋盘格上。
  这是图层面板里最像 PS 的一件东西，也是原来那个文字徽章（`流向`/`障碍物`）多余的
  原因——图层名本来就是这些字。
  只有**像素变了**才重取：落笔结束、填充结束、清空、撤销，以及任何结构性改动。
  拖不透明度不重取——PS 的缩略图显示的是内容，不是外观，而且每帧一次 IPC 换不到任何东西。
- **可见性列是两个形状，不是一个形状加一道线**：眼睛＝显示，空心方格＝隐藏，
  而且眼睛取更亮的颜色。划线眼每一行都要解码一下；眼睛对着方格是一列可以直接扫下来的
  信息，加上明度差，答案就是「哪些是开的」而不是「这个符号什么意思」。

面板内的 `▸` / `▾` 是 SVG，不是文字。这两个码位不在所有 UI 字体里，9px 的 `▾` 在
Windows 上渲染成一个小点，读起来像项目符号而不是展开控件。

### 开关长在它管的那几行上

`视图` 原来是「一格里四个复选框 + 一节里五条滑轨」。没有东西说明哪个开关管哪条滑轨，
而 `速度` / `强度` 明明都归 `播放动画` 管，却只有一条挨着它。

改成 PS `图层样式` 的语法：勾一个效果，这个效果自己的设置在它下面缩进展开。
归属关系成了几何关系，不用记。

```
▾ 叠加
  ☐ 天空贴图
      不透明度  [———] 60%
  ☐ 叠加 Flowmap
      不透明度  [———] 80%
  ☑ 流向箭头
      密度      [=——] 48
▾ 动画
  ☑ 播放动画
      速度      [===] 1.00
      强度      [==-] 0.25
```

（`障碍层属性` 的「绕开障碍物流动 + 范围」也是同一套。）

- **缩进 19px**＝复选框宽 + 间距，参数对齐开关的**文字**而不是它的方框。
  对齐方框会让参数比它所归属的那个词还靠左。
- **开关不做变暗**。它就是你用来把这一组重新打开的那个控件，让它变灰等于
  把唯一可点的东西藏起来。变暗的只有它管辖的参数行。
- 开关必须是真正的 `<label>`，文字也是命中区——13px 的方框本身太难点，
  而且你瞄的本来就是那个名字。

### 不适用的控件变暗，不消失

`视图` 面板勾一个复选框，下面的参数**不再长出来**。

原来是 `参数` 整节包在 `{(showReference || showFlowMap || …) && (…)}` 里，行也是每行一个
条件。于是勾第一个框会一次插入「分节标题 + 通篇分隔线 + 一行」，把整列往下推 60px 左右：
你点了一个复选框，然后你正要点的那个东西已经不在指针底下了。

PS 的规则相反——面板里的控件是**固定的一组**，不适用的那些变灰。现在的做法：

| 场景 | 以前 | 现在 |
|---|---|---|
| 视图 · 五条滑轨 | 整节按条件渲染，每行按条件渲染 | 五条常驻，`off={!showX}` 变暗 + `disabled` |
| 障碍层 · 范围 | `disturbance_enabled && <Row>` | 常驻，`off={!disturbance_enabled}` |
| 文档 · 张角 | `projection === 'polar' && <Row>` | 常驻，`off={projection !== 'polar'}` |

两个副产品：

- **高度只由面板决定，不由当前状态决定**。滑轨下面的东西不会再自己走开。
- **顺带成了说明**：一行常驻的「叠加 80%」告诉你叠加 Flowmap *有*不透明度这个东西，
  以及它关掉时是多少——一行「只在开启时存在」永远说不出这句话。

变暗是**逐元素**的（`.row.off` 的标签与数值框各自降色），不是整行 `opacity`：整行统一
淡化会把数值一起读不出来，而数值恰恰是最该留着的那部分。滑轨则显式写
`input[type=range].rng:disabled`——`appearance: none` 之后浏览器自带的置灰不再生效，
只写 `disabled` 属性看着跟可用的一模一样。

### 不透明度在图层卡片里，模糊是挂在图层上的效果

这两个原来都躺在「属性」面板里，紧挨着。它们不是一类东西：

- **不透明度**问的是「这一层往下透多少」，是**图层栈**的问题，不是这一层内容的问题。
  PS 把它放在图层面板顶部、列表之上，一个控件永远指当前选中层。它在那里。
- **模糊**不是像素的属性，是**事后对像素做的事**。PS 的对应物是 `fx`——图层名右边那个
  徽章，以及缩进在图层下面、可以逐条开关的那几行。

所以效果是一条**记录**（种类 + 开关 + 量），不是「某个模糊量」这个字段：

| 由此能做到 | 因为 |
|---|---|
| 一层挂多个效果 | 列表，不是字段 |
| 关掉一个但**留着调好的数** | `enabled` 与 `amount` 分开，可以 A/B |
| 「加一个效果」是个动作 | 工具栏的 ✦ 按钮，不是一个凭空出现的滑轨 |
| 删掉之后**逐字节回到原样** | 记录没了就是没了，不会残留一个 0 |

细节：

- **徽章给每一层，不只给选中层**。它的用途就是回答「哪几层在对自己的像素动手」，
  而问这个问题的时候你多半不在那一层上。
- **效果行缩进 31px**＝缩略图那一列，所以效果的小眼睛落在图层眼睛的下面。
  行的形状（眼睛 / 名字 / 量 / 删除）也是照图层行来的，因为它就是图层的平行物。
- **关掉的效果变暗，不消失**——和面板里每一行同一个规则。它的量必须继续可读，
  因为那是这个效果回来时要用到的数。
- **两条模糊取大的那条，不叠加**。叠出来会得到一个两条滑轨都不写的半径，那比二选一更糟。
- **障碍层没有效果**（`NO_FX`）。它贡献的是一张遮罩，没有可模糊的像素；
  给它一个模糊，就是给一个什么都不做的控件。

引擎侧是 `engine/effect.rs`，前端镜像在 `src/effects.ts`（纯函数，字段一一对应）。
工程文件从 v1 升到 v2：`ProjectV1::upgrade()` 把旧的 `blur` 字段翻成
`vec![LayerEffect::blur(blur)]`，老工程打开后模糊还在原位。

### 拖这条滑块为什么曾经是卡的

模糊是**整幅画布**的事，所以每动一格就要重算一次。刚做出来时 1024² 一格要
**92 ms**（约 10 fps），三处原因，都不是"模糊太贵"这种笼统解释：

| 原因 | 数字 | 处理 |
|---|---|---|
| 垂直 box pass **每行派一个 rayon 任务**，里面再嵌三个 | 1024² 一个 pass **20 ms**，横向才 1.7 ms | 改成按**列条**切：一条任务走完整列，1024² **0.85 ms** |
| 横向 pass 每像素每通道两次 `rem_euclid`（`idiv`） | — | 换成加减的环绕，除法去掉 |
| 三个缓冲区 + 每 pass 一次全图 `copy_from_slice` | 4096² 每帧 3 × 67 MB 纯 memcpy | 两块乒乓，回写进 `a`；scratch 用 `thread_local` 复用 |
| 每一帧 input 事件都发一次 IPC，还 `saveHistory` | 排队，尾巴永远是过期值 | 合并：**最多一个在飞**，最新的那个等它；历史只给点击，不给拖动 |

1024² 一格 **92 → 9.7 ms**（9.4x），4096² 716 → 124 ms。常规合成不受影响
（1024² 一笔仍是 0.18 ms）。

两条并行上的经验，写在这里是因为它不只在模糊里成立：

- **别按行切。rayon 的任务数要由工作量决定，不由行数决定。** 每行一个任务是
  1024 个任务，而每个任务只有 4 KB 的活——调度开销比活本身贵。按列条切是 16 个
  任务，每个走完整个 y。
- **热点像素循环里不要有 `idiv`。** `rem_euclid` 看着是个函数调用，实际是一条
  除法指令，而窗口偏移本来就在 `(-w, 2w)` 里，加减就够了。

`the_vertical_box_pass_matches_a_naive_blur_across_every_strip` 用**朴素实现**
（每输出像素一次完整求和）逐字节比对，宽度专门取了除不尽的 100，好让最后一条
是残条——列条的接缝是这次切分唯一可能错的地方。

### 面板栏是个 dock

拖标题栏就能重排面板，落点用一条蓝线标出来（PS 也是这么标的）。

- **拖动句柄在标题栏上，不在面板容器上**。挂在容器上会把整个面板体——包括所有滑轨
  ——都变成拖动源。
- **落点可以是整张卡片**，不只是那 30px 的标题栏。命中测试取「最近的卡片」，
  顺带把卡片之间 4px 的空隙也解析掉，而不是丢掉这次重排。
- **顺序是会话内的状态**，不落盘。PS 会记住工作区，但那需要一个「重置面板排列」的
  出口，否则用户拖乱之后没有回头路。要持久化就先把重置加上。

### 重排用指针事件，不用 HTML5 drag-and-drop

面板 dock 和图层列表的拖拽原来都是 HTML5 DnD（`<div draggable>` + `dragstart` /
`dragover` / `drop`），**而 `dragstart` 在这个 WebView2 里根本不触发**——代码接得
没错，但两个功能都像从来没接上过。

现在统一走指针事件（`pointerdown` + `setPointerCapture`），也就是分隔条、画笔、
笔刷参数拖拽已经在用的那条路，那些是确实在工作的。

- **4px 阈值**：不到 4px 就是一次点击，该折叠折叠、该选中选中。少了这个阈值，
  点面板标题时手抖 1px 就会静默取消折叠。
- **拖拽结束会补一次 click**（按下和抬起都在同一个元素上），所以要用
  `swallowClick` 吃掉正好一次——否则刚拖完面板，它又被折叠了。
- 图层行同样改成指针事件，所以图层顺序现在真的可以拖了（以前只有 ▲▼ 按钮能用）。

#### `setPointerCapture` 不能在 `pointerdown` 里调

指针捕获**连同兼容鼠标事件一起重定向**，所以按下时捕获，紧接着的那次 `click`
就会落在大元素上、而不是你真正按到的东西上。图层行是可拖的，而眼睛按钮在行
里面——于是点眼睛变成「click 落在行上」：`updateLayer` 根本没跑，眼睛纹丝不动，
表现就是**显示/隐藏失效**，而且看着像"只是选中了这一层"。

捕获挪到**过了阈值之后**：那时已经没有 click 可丢了。代价是阈值之前没有捕获，
所以 `pointermove` 得挂在 `window` 上——否则横向一甩就出行，4px 还没攒够，
手势就永远起不来。

面板标题栏不受影响，因为捕获元素和点击元素就是同一个 `<button>`。

### 面板里放状态，菜单里放动作

这是这一轮 reorganise 的唯一标准，PS 一直这么分：

| 原来的面板 | 现在 | 理由 |
|---|---|---|
| 图层 | 图层（移到属性下方） | 一直在动，但生成列表，放第二 |
| 属性 | 属性（移到最上） | 跟随选中图层，PS 也放右上 |
| *（浮在画布上的那条）* | **视图** | PS 从不在画布上挂控件；四个开关改成勾选框 |
| 投影 + 图片源 | **文档**（默认折叠） | 两者都是「这个文档是什么」，一个工程设一次 |
| 导出 | 导出（默认折叠） | 动作进菜单，只留分辨率/反转这两项设置 |
| 最近打开 | 文件 > 打开最近 | 路径列表不是文档状态 |
| *（HTML 顶栏）* | 删除 | 窗口已有原生标题栏且挂着菜单；重复的第二行 |

顺带：原来 HTML 顶栏的「新建/打开/保存/导入/导出」跟右侧的「图片源/导出」面板是
**同一个功能的两个入口**，删掉顶栏后 chrome 少一整行，画布更高。

吸管和平移既可以是工具，也可以是修饰键：任何工具下按 `Alt` 都是临时吸管，中键始终是平移。

## 笔刷

笔尖是**到线段距离的标量场**，不是一串圆形图章：

- 一次笔画里每个像素只写一次，所以拖快拖慢的边缘剖面完全一致。
  旧的图章叠加会让 alpha 变成 `1-(1-a)^n`，n≈10，边缘被越叠越硬——这正是
  「每个画笔间隔有明显接痕」的来源。
- 覆盖率取**并集（max）**而不是 source-over 累加。累加会让相邻笔段的重叠处
  比两侧更实，沿笔画按采样间隔周期性凸起（串珠）。取并集后整条笔画等价于对
  整条折线做一次距离场求值，边缘完全平滑；副作用是反复涂抹不会堆积不透
  明度（和 Photoshop 一致）。
- 剖面 = **实心台面 + 圆肩**：`核心 = 半径 × (0.40 + 0.59 × 硬度)`，肩部用
  smootherstep（两端一阶、二阶导数都为 0，接缝处不会出现马赫带）。
  台面下限 0.40 是关键——旧的 `核心 = 半径 × 硬度` 在硬度 0 时完全没有实心
  区，整支笔退化成一片雾。在**矢量场**里这比难看更糟：两笔的雾区重叠处，
  8 位 RG 存的是一个既不属于 A 也不属于 B 的方向，3D 预览里就是边缘那层
  噪点。Blender 的 soft 笔刷之所以好看，就是因为它保留了这个实心主体。
- `硬度` 默认 0.25（台面约 55%）；即使拉到 1.0 也保留 1px 过渡，不会出现锯齿硬边。
- 2D 光圈和 3D 光标都按同一条剖面绘制（`src/brush.ts` 与 `FlowShader.ts` 里
  的常数必须与 `ops.rs` 同步），且都受 `强度` 控制峰值不透明度。改一处要改三处。

#### 笔刷 HUD：`Alt` + 右键拖动

Photoshop 改笔刷的那一下（左右改直径、上下改硬度）在**右键**上，原因是 `Alt` +
左键在任何工具下都是吸管——修饰键已经被占了，所以手势只能去另一颗键。这里照抄
这个分配，2D 和 3D 都一样。

两个容易做反的地方：

- **向下是变硬。** Adobe 只写了「向上或向下拖」，方向得自己试：`dy` 是向下为正，
  所以硬度直接加 `dy`。向上是变软。
- **拖动期间光圈要还给笔刷。** Alt 按着，光圈本来是吸管的十字，而
  `.paint-cursor.picking` 是 `14px !important`——留着它，整个手势期间光圈都钉在
  十字大小，正是这个手势要改的那个东西反而看不见。所以 `showPicking` 读
  `adjusting`：擦洗期间它一律不点亮十字，松手时再按 Alt 的真值恢复
  （松开鼠标 ≠ 松开 Alt）。

3D 那边同一个手势还要跟 UE 式的右键转镜头分开：右键按下时若已经在擦洗笔刷，
window 上的 `mousedown` 监听就不点亮 `rightDown`，否则镜头会跟着一起转。

`F` / `Shift+F` / `Ctrl+F` 的左右拖动仍然保留，它们和 HUD 是同一个
`adjusting` 状态，所以光圈的表现完全一致。

#### 光圈不能被卡成吸管

按住 Alt 时光圈变成 14px 的十字，靠的是 `.paint-cursor.picking` 里的
`width: 14px !important`——它把「笔刷多大」整个盖掉。所以这个类一旦比它的 Alt 键
活得久，光圈就**永久停在十字大小**：大小滑块、F 拖拽、`[` `]` 全都像坏的，
而 3D 那边没有这个类，一直是好的。这个不对称就是症状。

Alt+Tab 或者点了别的窗口，keydown 到了、keyup 没了，于是卡住。修法是让这个类
不只由一个地方写：窗口失焦时放下、指针移动时按 `e.altKey` 对账（指针事件带着
Alt 的真值）、任何不带 Alt 的按键落下也顺手清掉——这样卡住的状态活不过一次鼠标
移动，也活不过你用来发现它的那次 F。

### 选项栏是两个一组，不是一个列表

`大小 · 硬度 │ 强度 · 透明度`。**两两成对，用一道竖线分开**，因为它们回答的是
两个不同的问题：

| 组 | 参数 | PS 类比 | 含义 |
|---|---|---|---|
| 笔尖 | `大小` | 大小 | 多宽 |
| 笔尖 | `硬度` | 硬度 | 边缘多硬 |
| 颜料 | `强度` | 前景色 | 想画到的**流动强度上限**，是天花板 |
| 颜料 | `透明度` | 流量（方向反过来读） | 每一笔落下多少 |

四个滑块排成一排是四把互不相干的尺子；成对之后，前两个说的是**笔尖**，后两个
说的是**画上去的东西**。这就是 PS 画笔面板的分法（画笔笔尖形状 / 传递）。

#### 强度带一个色块

强度**就是**前景色：它是一笔画过去的那个目标值，也是笔刷里唯一会留在像素上的
东西。所以它拿到了 PS 给「你画画用的那个东西」的唯一一件家具——一个色块，亮度
就是值。下限是深灰不是黑：强度 0 时融进面板的色块读起来是「坏了」，不是「没有」。

四个读数一个单位一件事：`大小` 是像素，其余三个都是百分比。混着 0.25 和 25%
会让人在两个滑块之间做心算。

#### 强度是上限，透明度是速率

```
实际强度_n = 强度 × (1 - (1 - 透明度)^n)
```

滑块右端是**一笔到位**（不透明），左端几乎不落东西。数字键 `1`–`0` 直接设这个
值（`4` = 40%，`4` `5` = 45%，`0` = 100%），所以滑块**必须按 PS 的不透明度那样
读**——满格 100% 且最实。若印成它的补数（满格 0%），按 4 会看到滑块跳到 60，
数字键就成了坏的。这是「标签和滑块绑定值可以反向」的反面：**键盘怎么输，数字
就怎么念**。

透明度 100% 一笔到位；40% 要涂七八笔才接近上限，无论涂多少笔**都不会超过你设
的强度**。想画一片弱流动区域，它就一直是弱流动。

数字键改哪一边取决于当前工具，和 PS 一样：**画笔 / 橡皮擦**改笔刷的透明度，其它
工具（**钢笔、吸管、平移、魔棒**）改**选中图层的不透明度**。钢笔不在这个名单里
是故意的：一条路径只画一遍，没有「每笔落多少」可设，给它一个会连能动的滑块都没
有，数字键看起来就是坏的。

自动重复要挡掉：按住 `4` 每 ~30 ms 再来一次，会 40% → 44% → 40% 地闪。

曾经把两者合并成一个（强度同时当速率、天花板锁死满强度），结果是弱笔刷越涂越
强——在矢量场里这是错的，"这块流得慢"是一个明确的意图。

**沉积全部放在覆盖率上，颜色直接写最终值。** 若颜色也跟着淡入，两者会相乘，
实际观感变成 `(1-(1-透明度)^n)²`：透明度 50% 时第一笔只有 6% 而不是 25%，得涂八
笔才看得见。而且方向并不会因此突变——你看到的是合成结果
`alpha × 我的方向 + (1-alpha) × 风向`，矢量是随覆盖率上升**旋转**过去的。

实现上有三个坑，都踩过：

1. **同一笔之内不重复沉积。** 引擎为每个像素记一份「本笔画已沉积的权重」，
   只在 `stroke_id` 变化时清零——也就是每次按下鼠标。否则一笔之内的自身重叠
   会不断叠加，笔画中段饱和而两端仍淡，等于把串珠问题换个皮又放回来。
   前端每帧只发一个批次，所以 `stroke_id` 必须由**按下**驱动，不能由批次驱动。
2. **alpha 要从颜色写入之前的值起算。** `write_union` 会把 alpha 设成覆盖率
   并集，若从那个值再插值，覆盖率就被钉死在笔刷自身值上，透明度再高也照样满覆盖。
3. **橡皮擦只退覆盖率，不动 RGB。** 两边一起退会变成平方衰减，擦除速度只有涂抹
   的一半；而且这正是 canvas `destination-out` 的语义。

另外：撤销 / 重做 / 清空 / 魔棒 / 改分辨率都会作废累积记录——累积量是相对像素的
增量，像素被整体替换后必须重来。

遮罩层（风向 / 障碍）不参与沉积——它的 alpha 本身就是载荷，没有「趋近的目标」。

## 钢笔：一条路径就是一条流向

画笔的方向取决于你手划出来的那一下。这对点涂是对的，但 flowmap 最需要的东西恰好是它
最做不好的：**横跨整片天空、一路缓慢转弯的一道流向**。用拖拽画那是所有笔画里最难的一种，
而这正是钢笔存在的理由——放几个锚点，曲线就是精确的。

```
点击放锚点 → 在锚点上按住拖动拉出手柄 → 点首个锚点闭合 → Enter 落笔
Backspace 退掉最后一个锚点 · Esc 放弃整条路径 · P 切到钢笔
```

路径被离散成一条 UV 折线后交给 `stroke`：折线本来就是引擎的工作单位，它从每一段的
行进方向推出流向向量，所以路径的切线天然就是流向，不需要任何新的绘制通道。

| 决定 | 为什么 |
|---|---|
| 拖动只管弧度，不落笔 | 钢笔不设 `drawing` 标志，锚点放下之前画布上一个像素都不动 |
| `(0,0)` 手柄 = 平滑，不是尖角 | 单击不拖也必须给出曲线。若 `(0,0)` 表示"没有手柄"，每个普通单击都会得到一段直线，这工具就只有已经知道要拖的人才能用 |
| 手柄镜像 | 拉一边，锚点两侧一起弯——用过钢笔的人都指望这个 |
| 首锚点画成蓝框 | 点它可以闭合路径，看不见的入口等于没有入口 |
| 闭合 / 拾取判定用**屏幕像素** | 那是一次点击，缩放前后手感必须一样 |
| 覆盖层画在 `props.size` 的画布上 | 和它即将变成的像素共用一套坐标，平移缩放跟着走——和箭头图层同一套路，不用 SVG |
| 3D 视图里停用 | 3D 没有能画路径的覆盖层，会落到 `onPaint` 的兜底分支变成普通画笔——那比不能画更糟 |

几何全在 `src/pen.ts` 里，纯函数、UV 空间、无 DOM，所以能直接单测（30 条）。

### 路径是非破坏性的：锚点才是对象

画笔落下去，留下的是像素——你原本想画什么，画布不知道。钢笔不这样：**锚点是对象，
像素只是它的一次渲染**。所以这个工具其实更像 Substance Painter 而不是 Photoshop：
一条路径落地之后仍然可以选中、拖动、改弧度、换笔刷，像素跟着重算。

```
落地之后：点线身选中 → 拖锚点改形状 · 拖手柄改弧度 · 拖线身整体移动
Alt + 锚点 删除该锚点 · Alt + 线身 在该处插入锚点
Alt + 空白处 仍然是吸管（见下），不会顺手放一个锚点
Backspace 删除整条 · Esc 取消选中
```

| 决定 | 为什么 |
|---|---|
| 路径存在**路径图层**上（`LayerKind::Path`） | 流向图层存的是像素，而像素恰恰是路径最不能被还原成的东西——一旦变成像素，它就不可编辑了。选钢笔时会自动建/切到路径图层，而不是拒绝落笔 |
| 笔刷跟着路径走 | 每条路径自带 大小/强度/硬度。否则"把第 3 条改粗一点"就得重画一遍，而且会动到第 4 条。选中后选项栏的三个滑块说的就是**它**，不是下一笔 |
| 编辑发的是几何，不是像素 | `set_paths` 把整份锚点列表交给引擎重渲染。画上去补一笔会留下擦不掉的残影 |
| 只重算**动到的那一块** | 每层几十条路径时，拖一条不该付出画全部几十条的代价。脏矩形先取"变化路径的旧框 ∪ 新框"，再把与它相交的路径一并纳入重绘（相交的路径会被这次清除擦掉，不重画就缺一块） |
| 拖动对**按下时的副本**取绝对差值 | 逐帧累加增量会攒误差，掉一帧还会漂。绝对路径永远在你放手的地方 |
| 一次手势一步撤销 | 拖动途中不发历史条目，只有 `done` 那一次记。单纯点选（没移动）完全不记 |
| 撤销要还原几何 | 只还原像素会让覆盖层显示一批和流场对不上的锚点，下一次拖动就会把路径弹回去 |
| 分辨率无关 | 锚点在 UV 空间，改尺寸是**按锚点重渲染**而不是拉伸旧光栅——这是烘焙过的笔迹永远做不到的事 |
| 选中才显示锚点 | 每条路径都把锚点摊开就是一片看不清曲线的方格网，而锚点本来就一次只能编一条 |

### 吸管：按住 Alt 吸取强度

和 Photoshop 一样，按住 Alt 临时变成吸管，吸取光标下的**流动强度**并写回「强度」
滑块；松开自动回到原工具。2D 和 3D 视图都支持。

- **取样来源**（底部栏的下拉，对应 PS 的取样选项）：
  `当前图层`（默认，只吸你正在画的那一层）/ `合成结果`（所见即所得）。
  风向 / 障碍层的载荷是遮罩，没有强度可言，选「当前图层」时会自动退化到合成——
  否则遮罩的纯白会被读成满强度。
- **3×3 平均**，不是单像素：8 位量化会让单点抖动，吸出来的值不是你画的那个。
- 水平方向按等距柱状**环绕**取样，接缝两侧读到同一个值。

Alt 原先在 2D 里是平移的别名（原版 Web 版就这么绑的），现在让给吸管；
平移保留**中键**——那本来也是原版绑的键，功能没丢。

## 流动动画：2D 动的是箭头

3D 视图把一张天空贴图按流场推着走，2D 没有贴图可推——这里能动的只有**箭头**，
而箭头恰好就是「流向」本身。所以 `播放动画` 在 2D 里让箭杆的虚线顺着流场往下
游走，速度和 3D 用同一个数（`animating ? speed : 0`），`Space` 两边一起开关。

三个细节：

- **虚线偏移是递减的**（`lineDashOffset = -dash`）。箭杆是从尾画到头的，所以
  偏移递增会让虚线**逆着**流场走——那比不动更糟。用真实 Chromium 量过：偏移
  `-3` 的第一段虚线比 `0` 的靠后 3px，也就是往头那边走了。
- **暂停时回到实心箭杆**，不是停在某个相位。静帧是用来**读**的，虚线只在动起来
  的时候才有意义。
- **每一帧不重采样**。采样要把合成图画到 128² 再 `getImageData`，一次笔画做一次
  可以，60 Hz 太多。所以几何（`Path2D`）缓存下来，一帧只剩：清屏 + 一次描边 +
  一次填充。

`animating` 默认 true——改之前它在 2D 里是个什么都不动的开关。

## 相比 Web 版的性能改进

| 环节 | Web 版 | 桌面版 |
|---|---|---|
| 图层合成 | Canvas 2D，单线程，同步 | rayon 并行，SIMD 友好的 `par_chunks_mut` |
| 风向场生成 | 512² 再放大（精度损失） | 全分辨率并行生成，无降采样 |
| 障碍绕流 | 1024² `getImageData` 往返 + 逐像素 | 原地并行计算，零往返 |
| 无缝模糊 | `ctx.filter` 全分辨率 | 3 次可分离盒式模糊（≈高斯），环绕采样 |
| 笔刷反馈 | 每次事件重绘 + React 重渲染 | 每帧 1 次 IPC，脏矩形传输，React 零重渲染 |
| 合成分配 | 每层每帧新建 canvas | scratch buffer 复用，热路径零分配 |
| 撤销栈 | 每层 4MB 原始快照 | zstd 压缩（约 40:1），40 步 |
| 导出 | 主线程 `toDataURL` | Rust 后台，PNG/TGA，512²–4096² |

界面右下角有实时「合成 x.xx ms」指示器。

### 分区合成：只重算变了的那一块

上面那张表还漏了最大的一笔。在此之前，合成是**全画布**的：一个 64² 的笔触会触发整幅
1024² 的重算。而传输层早就只发脏矩形了（64² 约 0.07 ms），合成却是 265 ms —— 帧成本被
画布尺寸决定，而不是笔刷尺寸。

现在 `composite()` 只重建真正会变的矩形：

- 混合、遮罩、障碍 B 通道、绕流**都是逐点运算**——一个像素的输出只依赖同一个像素的输入。
  所以「图层哪里变了」就等于「合成哪里会变」。
- 唯一有邻域的是**模糊**，按 `blur_influence`（3 次盒式模糊的半径）扩边即可。
- 风向场、模糊副本、障碍 alpha 平面改为**按参数缓存**：参数没动就不重算。此前障碍平面是
  每帧重算的（降采样 + 模糊 + 提取），这才是 265 ms 里的大头。
- 行循环在低于 96 行时退化成串行——rayon 的调度开销对几十行的笔触矩形来说比循环本身还贵。

实测（release 构建，3 图层：风向 + 障碍 + 流向，`cargo run --release --example bench`）：

| 画布 | 改前（一笔） | 全画布重算（改后） | 一笔（改后） | 提速 |
|---|---|---|---|---|
| 512² | 15.75 ms | 1.74 ms | **0.20 ms** | ~79x |
| 1024² | 46.64 ms | 2.88 ms | **0.16 ms** | ~291x |
| 2048² | 136.73 ms | 10.48 ms | **0.52 ms** | ~263x |
| 4096² | 555.81 ms | 36.70 ms | **1.08 ms** | ~515x |

改前 4096² 一笔要半秒，等于 2 fps；现在 1 ms，且**成本几乎不随画布涨**（0.20 → 1.08 ms
跨了 64 倍像素量）——这才是分区合成真正要的东西：帧成本由笔刷决定，不由画布决定。

代价是正确性必须靠测试兜住——见
`a_region_rebuild_is_pixel_identical_to_a_full_one` 那几条。

## 抹掉「这是个网页」的痕迹

Tauri 用 WebView2 渲染界面，所以默认会连浏览器行为一起带上。`src/desktop.ts`
在 React 挂载前装上 `desktop-shell`，关掉这些：

| 现象 | 处理 |
|---|---|
| 右键弹出「刷新 / 另存为 / 检查」 | 全局 `contextmenu` 屏蔽（3D 右键拖拽也必须要） |
| `F5` / `F7` 刷新 | 屏蔽 |
| `Ctrl+R` / `Ctrl+P` / `Ctrl+U` | 屏蔽（`Ctrl+S/O/N/Z/Y/E/F` 是应用自己的，保留） |
| 触控板双指缩放整个界面 | 屏蔽 `ctrl+wheel`；`tauri.conf.json` 亦设 `zoomHotkeysEnabled: false` |
| 拖文件进窗口导致页面跳转 | 屏蔽 DOM 层 `drop` / `dragover`（真正的打开走 Tauri 事件） |
| 拖选文字 / 把图片拽出来 | 全局 `user-select: none`，表单控件与 `.selectable` 例外 |
| 浅色滚动条 | 换成深色细滚动条 |

**唯一无法用 CSS 隐藏的**是 Chromium 的指针锁定提示气泡
（`tauri.localhost — 要显示光标，请按 Esc`）——它是画在 DOM 之外的浏览器 UI。
所以应用**完全不调用 `requestPointerLock()`**，`F` / `Shift+F` / `Ctrl+F`
拖动改笔刷参数时用原始指针增量驱动。`app-wiring.test.ts` 会拦截任何重新引入。

### 2D 舞台必须永远是正方形

flowmap 是正方形 UV 空间，所以 `.paint-stage` 不能随面板形状变形。
`width:100%` + `aspect-ratio:1/1` + `max-height:100%` 看着对，其实不够：面板
**宽大于高**时高度被 clamp、宽度不动，图就被压扁——从分屏切到 2D 全屏就会触发，
所以它只是「有时」变形。连带两个副作用：笔刷光圈按百分比算，压扁后变椭圆；
`getUV` 用 canvas 的宽 / 高分别做分母，垂直方向的落笔位置也会偏。

现在两个轴都取 `min(100cqw, 100cqh)`（`.paint-view` 声明为 `container-type: size`），
包在 `@supports` 里，老引擎退回原写法。`app-wiring.test.ts` 有断言守着。

### 缩放围着指针，而且从画面外也能起手

中键 + Ctrl 上下拖是缩放，滚轮也是。两件事都很容易做错一半：

**围着画布中心缩放**，指针底下那一点会跑掉，于是「放大看这块」变成「放大之后
再拖回来找这块」。舞台是 `translate(x, y) scale(s)`，按自己的中心缩放，所以
画面上的点 `P` 落在

```text
screen = C + T + s * (P - C)
```

`C` 是完全没变换时舞台的中心。让屏幕点 `M` 在 `s` 变化前后不动，是一行代数：

```text
T1 = (M - C) * (1 - k) + k * T0        k = s1 / s0
```

`C` 没法直接问 DOM——能量的只有变换之后的盒子，而绕自己中心缩放不改变中心，
所以量出来的是 `C + T`，减掉平移就是了（`stageCentre`）。走 `offsetParent`
累加则要随布局改一次，而且面板一挪就错。

**只有按在画面上才起手**，画得小的时候画面只有中间一小块，指针在外面按下去什么
都不发生。所以手势挂在 **`.paint-view`（整个窗格）**上，而且挂在**捕获阶段**
（`onPointerDownCapture`）+ `setPointerCapture`：画布自己也在同一个窗格里，冒泡
到窗格的那一次同样起手，但目标缩放是**绝对值**而不是增量，第二次调用 `k == 1`
直接返回原对象——窗格和画布共享同一个 `moveView`，指针移动被两边都看见也不会
把缩放叠加两次。
